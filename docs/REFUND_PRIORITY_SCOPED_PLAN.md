# HIGH 风险观察限定的退款优先级修复：v2 预声明

2026-10-01（Europe/Paris）。v1全部92条validation已完成并拒绝；结果保留在results/refund-priority/v1。

## 为何修订及唯一差异

v1把优先级说明加到所有退款输入，结果LOW+FAILED误转人工，普通退款固定候选选择退步。
v2保持完全相同的澄清文本，只在family=refund且已授权observations明确包含customer.risk_level=HIGH时加入。
这是一项有限、确定性的显示条件：不看隐藏state、EOC、ID或Action，不发起工具或模型请求，不选择/替换Action。
control与priority均保留原allowlist转换；执行B、Gate、工具权限/事务/幂等和权重不变。

在175种任务族/已知或缺失风险/支付组合中证明：仅5种HIGH退款组合激活；另外170种序列化输入逐字相同。
还会对v1真实原始context（含Skill、历史、错误）逐条验证所有非激活输入在两臂逐字一致。
证据冻结包含v1完成清单与报告，明确这是看到validation失败后的新候选，不伪装为未调参评测。

## 评测与准入

干预现在只作用于已知HIGH退款，故本版研究验证范围明确限定为退款：原边界validation全部8个退款场景，两臂各一次完整任务与固定候选，共32条。
不同于v1的23场景分母，不能直接比较总分。本版两臂全部重新运行，不复用v1 control分数；其他任务族不另跑模型，以逐字输入不变性证明无显示干预。
本版未获得主项目产品准入，不能凭缩小后的研究范围宣布全项目无回归。

沿用v1联合门槛：EOC、正常完成、固定候选正确数均不低于新control；实际违规为零、模型违规尝试不增加。
通过后再做全部8个已见退款test场景，两臂两种评测各3次，共96条。研究诊断总上限128条，不是新的独立测试集。
顺序在模型调用前冻结；失败按原预算/EOC保留，基础设施失败停止。运行中不改提示或判分。

沿用v1状态链、请求字符串、响应指纹、检查点、bootstrap与阶段选择审核。
固定候选从已授权读取建立的冻结context重放；setup_read_equivalents是按次输入准备等价读数，HTTP阶段不重新执行读工具，不与完整任务实际工具调用相加。
若成功，归因于人工已知policy的显示条件修复；不是边界学习发现新规则。若失败，保留负结果，不自动部署。
