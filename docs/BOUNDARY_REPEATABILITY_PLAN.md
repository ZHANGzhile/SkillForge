# 边界实验重复性诊断：预声明

本方案在本轮模型调用之前冻结。上一轮结果全部保留；这是已观察问题的事后诊断，不是新测试集上的确认性实验。

1. 从已审核的216条真实轨迹（排除D别名）重建实际发送的JSON字符串，纳入全部2个动作分歧输入；按输入哈希排序选前2个历史稳定重复输入作对照；再纳入正常退款退步案例的A/B/C首个输入。去重后每个输入重复10次。
2. 全部8个正常场景均纳入，每个场景的A/B/C各自主执行3次，共72次。每次新建相同环境快照，执行程序、工具权限/policy、三态Gate、预算、模型和提示保持冻结。C/D同契约，因此本轮只执行C，不伪造D重复观测。
3. 两类调用混合，按固定seed与运行key的哈希排序执行；顺序、输入、代码、源证据、服务身份写入freeze.json。模型请求串行，不重启服务、不改后端、不调整seed、不重训。失败/分歧不触发择优重跑。
4. 每个请求保存原样用户字符串、返回Action、指纹、token与耗时；全任务保存完整状态链、工具审计、EOC、成本和首动作。逐条原子检查点，恢复前校验全部旧检查点。基础设施失败停止并单独留档，不作为模型失败；非法模型Action保留为模型输出失败。
5. 报告每个输入的Action频数（完整Action与type/name分别统计），正常任务逐场景逐组通过次数及调用成本。重复执行不是新增独立业务场景，不把24次当24个独立场景，不据此覆盖旧bootstrap或宣布满足旧联合门槛。
6. 若相同输入仍不同，只能确认本服务条件下存在输出变动；若10次相同，也不能推翻历史分歧。若B退款仍失败而A/C通过，支持该问题在固定服务下重复出现，但不能定位到某个谓词或CUDA算子。准确原因需另行设计后端/数值诊断，不在本轮改冻结服务。

本地代码审查发现：服务锁串行生成，do_sample=False；HTTP seed只校验，不逐请求重置随机状态；冻结后端为cudnn。以上是实现事实，尚非分歧的因果解释。

执行：`python -m scripts.evaluate_boundary_repeatability --freeze`，然后`--run`；只读审核与报告：`--audit`。实时记录见[BOUNDARY_REPEATABILITY_LIVE.md](BOUNDARY_REPEATABILITY_LIVE.md)。
