# 真实模型Skill演示交付

2026-09-15：可直接操作的三类业务演示已交付。

## 打开与运行

当前入口：http://127.0.0.1:8080/skill-demo 。服务仅监听本机。

重启电脑后，双击项目根目录的`启动演示.cmd`；或运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_demo.ps1
```

在页面选择修改地址、取消订单或退款，再选择正常、拒绝或高风险场景，点击“运行真实模型演示”。退款的拒绝场景是支付未成功。每次创建独立模拟订单。

页面展示模型决策、Skill内部工具执行、验证回执、状态变化、原始模型输入和选择，以及完整工具审计；可下载JSON轨迹。刷新带job参数的页面可继续查看该任务。

## 本次具体改变

原接口把完整契约放在长上下文中，模型始终偏向原子工具。本演示新增`MenuModelClient`，让模型在短而明确的动作目录中输出一个选择；服务端只按该选择绑定已给定的任务参数。

受限动作协议包含可执行Skill、读取、拒绝和转人工；不提供原子mutation。只有收到Skill成功且验证匹配的回执，才允许选择stop；已成功的Skill不会再次列出。模型仍可错误拒绝、转人工或重复读取，适配器不会将错误选择改为正确动作，接口失败也不会切换脚本策略。

Gate读取业务状态并过滤不适用Skill；这是已有运行时行为，不是新增Agent。拒绝还是转人工仍由模型判断。早期HIGH风险响应的理由提到转人工，choice却选择refuse；调整为先给简短业务理由、再选择动作后，三个训练场景通过。保留了此前失败轨迹。

## 能证明与不能证明的内容

已经证明：在这个受限动作目录和受支持的三个业务场景内，真实本地模型能够选择Skill，执行器能够完成工具调用与验证，页面能够展示完整结果。

这不是旧版B3成功率从47.4%提升到100%的实验。动作空间、提示表达和完成协议都已改变；27个validation案例也不是完整独立test。当前结果包含Gate、输入绑定、完成约束和Executor提供的系统能力，不能全部归因于模型或Skill学习。未进行权重训练。

下一阶段应将新协议作为明确的新实验配置，在保留旧基线的前提下验证更广的任务与故障场景，再评估训练是否必要。
